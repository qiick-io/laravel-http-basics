# Dependency register

Every runtime entry from the root `composer.json` `require` object is listed
below; `require-dev` is not. The register is reviewed at every release and in
every PR that changes `require`.

| Dependency              | Version constraint | Why this minimum                                                                                                   | What we use                                                                                                                                                                                                                     | What we replace or extend and why                                                                                                                                                                          | Maintainer               | License | Known risk                                                                                                                              | Exit plan within this package                                                                                          |
| ----------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ | ------- | --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `php`                   | `^8.3`             | Floor set at the scaffold (#1); the fleet standard for new packages. The CI matrix runs 8.3–8.5, and readonly classes need 8.2+. | Language runtime: readonly classes and DTOs, enums, `str_starts_with`/`str_ends_with`, first-class callables across `src/`.                                                                                                       | Nothing to replace; platform requirement.                                                                                                                                                                   | PHP Group                | PHP-3.01 | None known.                                                                                                                                | Not replaceable; the floor is raised deliberately per release.                                                          |
| `ext-fileinfo`          | `*`                | Any fileinfo build; the upload floor sniffs the real MIME type and there is no PHP fallback for `finfo`.              | `new finfo(FILEINFO_MIME_TYPE)` on the uploaded temp file in `src/Uploads/UploadValidator.php`; the detected MIME drives the extension map (`DetectedMimeExtension`), the archive/blocked lists (`HardFloor`) and `ValidatedUpload`. | Extends `Illuminate\Http\UploadedFile` validation: the client-declared MIME and suffix are never trusted, only the sniffed type decides storage extension and policy — a check Laravel does not provide. | PHP project (libmagic)   | PHP-3.01 | The magic database differs between OSes and libmagic versions, so a type may sniff differently across hosts; the allowlists are explicit MIME strings, mitigating drift.                                  | Swap `finfo` for a pure-PHP sniffer (e.g. mimey) or delegate scanning to the product's `MalwareScanner` seam if libmagic drift is observed. |
| `illuminate/cache`      | `^12.0 \|\| ^13.0` | Cache repository and lock primitives for the idempotency store; same major range as the rest of `illuminate/*`.          | `Illuminate\Cache\Repository`, `Illuminate\Contracts\Cache\Factory` in `src/Laravel/HttpBasicsServiceProvider.php`, `src/Idempotency/CacheIdempotencyStore.php`, `DatabaseIdempotencyStore.php` and `SealedKeyMarker.php`.                          | Extends the app's cache with package-owned idempotency records and atomic locks (`LockProvider`) instead of a bespoke store, so products pick the driver and TTLs stay in `config/http-basics.php`.          | Laravel (Taylor Otwell)  | MIT     | Lock and atomicity semantics differ per cache driver; the store relies on `LockProvider`, and the database store is the fallback for drivers without it (suggested `illuminate/database`, not required).       | Extract an `IdempotencyStore`-only contract already in place; swap the cache-backed store for a dedicated table/driver if a product outgrows it. |
| `illuminate/contracts`  | `^12.0 \|\| ^13.0` | The package binds against contracts, not implementations; same major range as `illuminate/*`.                             | `Illuminate\Contracts\Foundation\Application`, `Config\Repository`, `Translation\Translator`, `Validation\ValidationRule`, `Cache\Factory`, `Cache\LockProvider` across `src/Laravel`, `src/Idempotency`, `src/Locale` and `src/Contracts`.                    | Nothing to replace; depending on contracts keeps the surface minimal and testable — `Illuminate\Http\*` types still come from `illuminate/http`, which is required separately.                              | Laravel (Taylor Otwell)  | MIT     | Contract interfaces can gain methods between majors; the `^12 \|\| ^13` range must be re-verified on each new major.                                                        | Pin to the concrete component only if a contract proves unstable; the usage is a handful of interfaces.                               |
| `illuminate/http`       | `^12.0 \|\| ^13.0` | Request/response/middleware types and the HTTP client used for `X-Request-Id` propagation; same major range as `illuminate/*`. | `Illuminate\Http\Request`, `JsonResponse`, `UploadedFile`, `Middleware\TrustProxies`, `Client\PendingRequest` across middleware, error renderers, upload validation and `src/RequestId/RequestIdPropagator.php`; Symfony `IpUtils`, `ResponseHeaderBag`, `HttpException` arrive transitively through it. | Extends the framework's HTTP kernel: middleware slots into `web`/`api`, responses stay `JsonResponse`, and the propagator hooks `PendingRequest` so outbound calls carry the request id without a second HTTP client. | Laravel (Taylor Otwell)  | MIT     | `PendingRequest` internals are not a stability contract; the propagator uses the public `withHeaders` API. Symfony classes are transitive — a Laravel major could shift them.                                  | Port the propagator to PSR-18 if Laravel's client contract changes; middleware and responses are stable framework surface.               |
| `illuminate/support`    | `^12.0 \|\| ^13.0` | Foundation helpers, service provider base and facades; same major range as `illuminate/*`.                                     | `ServiceProvider` (`src/Laravel/HttpBasicsServiceProvider.php`), facades (`App`, `Context`, `DB`, `Schema`, `Vite`), `Str`, `Collection`, `Carbon` across `src/`.                                                                 | Nothing to replace; the package is a Laravel package and uses the framework's own helpers rather than duplicating them.                                                                                  | Laravel (Taylor Otwell)  | MIT     | Facade and helper APIs shift between majors; `Vite`/`Context` helpers are newer surfaces — re-verify on each major.                                                                                          | Inline the few helpers used (`Str`, collections) if a future major breaks them; they are a thin surface.                               |
